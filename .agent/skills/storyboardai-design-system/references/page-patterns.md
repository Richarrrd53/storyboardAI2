# Page Patterns

## Dashboard

Use as the primary golden reference for product atmosphere. Keep greeting, hero, quick actions, recent projects, and QC composition visually calm and aligned. Recent projects should use the shared ProjectCard family.

## Projects

Use the shared ProjectCard family. The page title, card grid, and primary page action should align to the common outer grid. Ordinary “new project/storyboard” actions must not inherit QC rainbow/diffuse glow.

## Generate

Treat Generate as the creation workspace reached from Dashboard/QC, not a separate wizard product. Reuse system typography, inputs, cards, buttons, surfaces, and blue interaction language.

On mobile, display current step, progress, and step count without squeezing all full step labels into one row.

Prefer one main vertical scroll owner. Keep header/workspace/action zones aligned to a deliberate content axis.

## Project Detail

Story View can stay light, card-based, and readable. On mobile, recompose desktop shot tables into native shot cards rather than preserving a wide desktop table as the primary experience.

Professional View may preserve horizontal timeline behavior and higher information density, but surrounding chrome should remain StoryboardAI rather than becoming a different dark NLE product.

## Template Library

Allow more content color than other pages, but treat it as category/content accent. Keep system controls, links, focus, navigation, and primary actions in the StoryboardAI system language.

On mobile, use horizontal category reels or stacking where appropriate; do not force wide desktop search/action rows to fit by shrinking them.

## Landing

Landing may use larger brand visuals and more expressive composition, but keep logo, blue, typography family, CTA family, film semantics, and motion DNA connected to the application.

## Login / Auth

Keep minimal and clearly StoryboardAI. Reuse brand identity and shared input/button language rather than creating a separate form theme.
